EasyPrice

Plataforma web para simulação de preços de frete rodoviário (LTL e FTL), baseada em regras de pricing e na metodologia cost-plus.

02Contexto

ProblemaUma cotação de frete combina rota, tipo de carga, modalidade e custos operacionais. Quando o cálculo vive em planilhas isoladas, as regras divergem entre usuários e fica difícil auditar como um preço foi formado.

AmbienteOperação de transporte rodoviário de cargas, com cotações nas modalidades LTL (carga fracionada) e FTL (carga fechada).

ObjetivoConcentrar a precificação em uma plataforma única: parâmetros explícitos, simulação reproduzível e acesso controlado.

  • Regras comerciais, parâmetros e dados são confidenciais e não são publicados.
  • A demonstração desta página usa um modelo didático com dados sintéticos.

03Estratégia de solução

Metodologia cost-plus: o preço parte do custo e aplica a margem-alvo. As regras ficam separadas da interface e os parâmetros são tratados como dados, não como constantes no código.

Decisões de engenharia e suas justificativas
DecisãoMotivo
Separar interface, serviço e persistênciaCada camada evolui sem quebrar as outras, e o cálculo pode ser testado sem a interface.
Parâmetros como dadosAjustes de margem e custo não exigem alterar o código.
Contrato de API tipadoFastAPI valida a entrada e TypeScript reduz divergências entre cliente e servidor.
Governança de acessoNem todo usuário deve consultar ou alterar os mesmos parâmetros.

05Implementação

O centro da solução é o cálculo de preço a partir de parâmetros. A interface coleta os dados da cotação, a API aplica as regras e devolve preço e margem de forma consistente.

Fluxo conceitual de uma simulação

  1. 01Entrada dos parâmetros da cotação
  2. 02Validação dos dados na API
  3. 03Aplicação das regras de pricing (cost-plus)
  4. 04Cálculo do preço e da margem
  5. 05Registro da simulação
  6. 06Apresentação e comparação de cenários

05.1Como o motor de precificação se organiza

Uma simulação atravessa quatro responsabilidades separadas: validar a cotação, resolver a rota, aplicar as regras de preço e registrar o resultado. Separá-las permite testar cada uma sem as outras.

Responsabilidades
ResponsabilidadeO que garante
Validação de entradaDados da cotação completos e coerentes antes de qualquer cálculo.
Resolução de cidadesNomes digitados de forma livre viram identificadores únicos de origem e destino.
Regras de preçoParâmetros lidos como dados, aplicados de forma determinística e reproduzível.
Acesso e governançaCada perfil consulta ou altera apenas o que lhe cabe.
RegistroCada simulação guarda os parâmetros usados, para revisão posterior.

05.2Arquitetura e implantação

A plataforma separa interface, API e banco. A documentação do projeto registra a entrada por IIS como proxy reverso HTTPS, na mesma origem do frontend, com a API escutando apenas em endereço local. O ambiente foi definido com a área de infraestrutura como uma VM dedicada, com SQL Server e ambientes de homologação e produção separados.

Com o SQL Server como fonte de verdade, uma simulação nasce no banco, recebe um identificador único e acompanha todo o fluxo: parâmetros, resultado, usuário, data e versão. Isso dá histórico e permite recuperar qualquer simulação.

Sensibilidade: preço × margem-alvo

A guia tracejada marca a margem escolhida. O preço sobe de forma não linear conforme a margem aumenta.

Premissas e cálculo

  • preço = custo ÷ (1 − margem): a margem é calculada sobre o preço. Para 20%, o markup equivalente sobre o custo é de 25,0%.
  • Os cenários alteram o custo e o volume por fatores fixos (ex.: custo +8% e volume −5%). Os fatores são premissas didáticas, não estimativas de mercado.
  • Resultado mensal = (preço − custo) × viagens. Valores arredondados a centavos.
  • Valores sintéticos. Nenhuma fórmula, parâmetro ou dado de empresa real é utilizado.

07Desafios

  • Regras que mudam

    Parâmetros comerciais mudam com frequência. Tratá-los como dados evita nova publicação a cada ajuste.

  • Rastreabilidade

    Para revisar um preço é preciso saber quais parâmetros foram usados. Isso orienta o registro de cada simulação.

08Resultados e aprendizados

  • Não há resultados quantitativos autorizados para divulgação.
  • Benefício esperado: padronizar a formação de preço e facilitar a revisão de cada simulação.

Separar a regra de negócio da interface torna o cálculo testável e reaproveitável por outros canais.
