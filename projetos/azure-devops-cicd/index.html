Azure DevOps e CI/CD: do código à produção

Como um fluxo de entrega transforma uma alteração de código em uma versão publicada com controle: revisão, build, testes, artefato, aprovação e ambientes.

Escopo
Conhecimento de engenharia de entrega. Não descreve um pipeline implantado em projeto meu.
Acesso
Este portfólio é publicado manualmente. Nenhum pipeline foi criado para ele.

01O fluxo

Tabela
EtapaObjetivo
Pull request e revisãoOutra pessoa lê a alteração antes de ela entrar na linha principal. Políticas de branch exigem revisão e build verde.
BuildCompila e valida o projeto em um ambiente limpo e reproduzível.
TestesFalha rápida: um teste quebrado interrompe o fluxo antes do deploy.
ArtefatoUma versão única e imutável, a mesma que será promovida entre ambientes.
Homologação e aprovaçãoValidação funcional e aprovação explícita antes de produção.
Produção e validaçãoPublicação controlada, verificação pós-deploy e plano de rollback.

02CI, entrega contínua e implantação contínua

Tabela
TermoSignificado
Integração contínua (CI)Cada alteração é integrada, compilada e testada automaticamente.
Entrega contínuaTodo build aprovado fica pronto para ser publicado; a decisão de publicar pode continuar manual.
Implantação contínuaTodo build aprovado é publicado em produção sem etapa manual.

Entrega contínua não implica deploy automático em produção. Muitas organizações mantêm aprovação manual por política ou por risco.

03Ambientes e configuração

  • Os ambientes (desenvolvimento, teste, homologação e produção) variam por organização; cada projeto usa os que fazem sentido.
  • O mesmo artefato é promovido entre ambientes. O que muda é a configuração, injetada por variáveis, nunca embutida no código.
  • Segredos ficam em cofre ou em variáveis protegidas, com acesso restrito por ambiente.
  • Rollback por versão anterior do artefato; o histórico de releases dá rastreabilidade.

04Azure DevOps na prática

Tabela
ServiçoUso
Azure ReposRepositórios Git com políticas de branch e pull requests.
Azure BoardsItens de trabalho e planejamento ligados ao código.
Azure PipelinesBuild, testes e entrega por pipelines versionados.
Azure ArtifactsPacotes internos, quando há bibliotecas compartilhadas.

05GitHub e Azure DevOps

Os dois oferecem repositórios Git, pull requests e automação de pipelines. Migrar um repositório entre eles preserva histórico e branches, mas exige recriar políticas de branch, permissões e pipelines no destino, e revisar integrações que apontavam para o endereço antigo.
