IIS e Windows Server: hospedagem de aplicações corporativas

Como o IIS recebe, protege e encaminha requisições para aplicações .NET e Python, e como autenticação, permissões e máquinas virtuais se encaixam nessa hospedagem.

Escopo
Conhecimento técnico de hospedagem Windows, ligado à documentação dos projetos. Topologia real não é publicada.
Acesso
Sem servidores, endereços, portas, domínios ou estrutura de permissões reais.

01O papel do IIS

O Internet Information Services é o servidor web do Windows Server. Em ambientes corporativos ele costuma ser a porta de entrada: termina o TLS, aplica autenticação e política de acesso, serve arquivos estáticos e encaminha o restante para a aplicação. Cada elemento de configuração existe por um motivo de operação ou de segurança.

Elementos do IIS e para que servem
ElementoFunção na hospedagem
Site e bindingAssocia nome de host, porta e certificado TLS a uma aplicação. É o que torna o endereço HTTPS válido.
Application PoolProcesso isolado que executa a aplicação, com identidade própria. Uma falha ou reinício não derruba os demais sites.
Identidade do pool e permissõesA conta que roda o processo recebe só as permissões de pasta e de banco de que precisa (menor privilégio).
AutenticaçãoAnônima, Windows ou outra, definida por site ou aplicação. Decide quem chega à aplicação e com que identidade.
URL Rewrite e ARRRegras de reescrita e proxy reverso: o IIS repassa o caminho escolhido para um serviço que escuta localmente.
LogsRegistro de requisições e erros, ponto de partida de qualquer diagnóstico.

02IIS como proxy reverso

No desenho de proxy reverso, o IIS fica na frente e a aplicação escuta apenas em endereço local. O usuário nunca fala diretamente com o processo da aplicação: isso concentra TLS, cabeçalhos e política de acesso em um único ponto.

03ASP.NET Core no IIS

No modelo de hospedagem do IIS, o ASP.NET Core Module recebe a requisição e a encaminha ao servidor Kestrel, que executa a aplicação. No modo em processo, a aplicação roda dentro do próprio processo do pool; no modo fora de processo, o IIS atua como proxy para um processo Kestrel separado. O Hosting Bundle instala o módulo e o runtime. Não existe configuração única: a escolha depende de desempenho, isolamento e operação.

04Serviço Python atrás do IIS

Uma API FastAPI não é uma aplicação ASP.NET: ela roda em um servidor ASGI, como o Uvicorn, que precisa de um processo mantido pelo sistema (por exemplo, como serviço do Windows). O IIS entra como camada de entrada, com TLS e proxy reverso para o processo local. Os papéis ficam separados: IIS recebe e protege, Uvicorn executa a API, a API aplica as regras e o banco guarda os dados.

05Windows Authentication e tokens

Tabela
ConceitoO que é
Windows AuthenticationO IIS autentica o usuário do domínio e repassa a identidade à aplicação. A senha não passa pela aplicação.
Negotiate, Kerberos e NTLMNegotiate escolhe o protocolo. Kerberos usa tíquetes do Active Directory e é o preferido. NTLM é o recurso de compatibilidade.
Autenticação e autorizaçãoSaber quem é o usuário é diferente de saber o que ele pode fazer. Grupos e perfis decidem as permissões.
JWT e OAuthTokens assinados para identidade entre serviços ou clientes sem domínio Windows. Não substituem a autenticação integrada: resolvem outro cenário.

Windows Authentication é adequada a aplicações internas em domínio. Tokens são necessários quando o cliente está fora do domínio, quando há integração entre serviços ou quando a identidade precisa viajar entre sistemas independentes.

06Máquinas virtuais

Pontos que sustentam uma VM de aplicação

  • Separar a VM da aplicação da VM do banco isola falhas e permite regras de rede distintas.
  • Firewall com portas mínimas: somente a entrada HTTPS fica exposta; o banco aceita apenas a origem da aplicação.
  • Recursos dimensionados por medição de uso, não por estimativa.
  • Backup e restauração testados, com logs retidos e consultáveis.
  • Contas de serviço próprias, sem privilégios de administrador.
